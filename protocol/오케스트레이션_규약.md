## 🔴 LB 적합 규율 (2026-08-23 사용자 결정 — 정찰이 운영진 FAQ 3건을 확인한 뒤)

사용자 지시: *"너무 과도하게 LB로 적합하는건 지양하고 그래도 하나 제출로 하나 적합 정도는 괜찮을거 같은데"*

**근거 (관측)**: 운영진이 같은 방법을 쓰는 팀 셋에게 답을 달았다 —
- 상수 **2점** 꼭지점 + 측정 제출 1회 → 🟢 *"허용 범위에 해당합니다"* (08-21)
- 상수 **3점** → 2차식 꼭지점 계산 → 사용 → 🟢 *"후보값 비교·보간은 허용되는 범위"* (08-19)
- 전역 보정 상수를 **2~3회** 제출해 최고점 채택 → 🔴 *"권장하지 않습니다"* · *"반복 횟수와 탐색 방식에 따라 리더보드 프로빙으로 판단될 수 있습니다"* · *"과도한 리더보드 탐색으로 결정된 값으로 판단되면 규칙 위반 여부를 별도 검토"*

**경계는 방법이 아니라 규모에 그어졌다.** 2차식 꼭지점 해법 자체는 세 번 연속 허용됐다.

### 🟢 2026-08-23 사용자 최종 판단 — 이 절의 규칙보다 이것이 위다

사용자: *"너무 과하고 노골적으로 LB에 맞추는 게 아니라 **'이 상수는 이러한 특성을 반영하여 넣었다, LB 측정 후 이러한 계산을 통해 약간의 보정을 거쳤다'** 이 정도의 서사면 이해해줄 거야. 무엇보다 **어차피 순위권 못 들면 검증이고 뭐고 없어**"*

**두 가지를 뜻한다:**
1. **각 상수에 실질적인 서사를 붙인다.** *"어떤 특성을 반영해 넣었고, LB 측정 뒤 계산으로 약간 보정했다"* — 그리고 **우리 축은 대개 실제로 그렇다**(exp_078·exp_082·exp_083 의 로컬 측정에서 나왔다). 계획서·`blend.json` 에 그 출처를 **사실대로** 적으면 그것이 서사이자 소명이다. 지어내지 않는다.
2. **위험 계산의 우선순위가 정해졌다.** 순위권에 못 들면 검증 자체가 없다 — 관측과 일치한다(08-13·08-18 삭제분은 **전부 상위권**이었다). 따라서 **프로빙 위험을 이유로 점수 기회를 접지 않는다.**

⚠️ 남는 규율 하나: **노골적인 형태를 피한다.** 한 후보에 새 축을 무더기로 싣거나 같은 상수를 여러 번 스윕하는 모양은 만들지 않는다. 축은 대체로 하나씩, 진폭은 작게.

### 지금부터의 규칙 (위 판단의 하위)
1. 🔴 **한 제출에 새로 적합하는 양은 하나.** 이미 값을 치른 꼭지점에 착륙시키는 것(재적합 아님)은 함께 실어도 되나, **새로 LB 로 결정하는 양은 후보당 1개**다.
2. 🔴 **폐기하는 것은 *규모*다 — 프로브 자체가 아니다** (2026-08-23 사용자 정정: *"그냥 싸게 잴 수 있게 해"*).
   - ❌ **폐기**: exp_081 의 `m=20 직교 방향 매수` 설계, 한 후보에 새 축을 여럿 실어 동시에 사는 `G⁻¹L` 다축 매수. FAQ 가 지목한 *"과도하게 반복하여 정답 평균·분포를 역추정"* 이 이것이다.
   - 🟢 **유지**: **작은 진폭 프로브 → 읽기 → 꼭지점 착륙**의 한 벌. 운영진이 세 번 허용한 형태가 정확히 이것이다(2~3점 보간, 축 1개). **프로브는 싸게 유지한다** — 진폭을 키우면 `G` 오차만 사 오고(S42) 하방만 커진다.
3. 🟢 **로컬 근거가 먼저다.** 새 축을 *고르는* 근거는 정직면·OOF·순열 귀무 등 **LB 밖**에서 온다. LB 는 그 축의 **크기**를 정하는 데 쓴다 — 축 자체를 LB 로 낚지 않는다.
4. 🟢 **이미 산 값의 활용은 계속한다** — 지나간 LB 점에서 유도된 꼭지점에 착륙시키는 것은 새 탐색이 아니다.
5. ⚠️ **기록은 그대로 유지한다.** 08-18 답변이 *"도출 근거·과정까지 검증"* 이라 했고, `BUILD_PLAN_*`·`EXPERIMENTS.md`·`CV_LB.md` 가 그대로 소명 자료다. 숨기지 않는다 — **각 상수가 로컬 근거에서 나왔음을 계획서에 명시**하는 것이 최선의 방어다.
6. ⚠️ 현황: 누적 제출 **90회**(상한 500), 축 15개 이상. 지나간 것은 되돌릴 수 없고, **더 키우지 않는 것**이 이 규율의 목적이다.

- **서브에이전트 보고서를 재서술하지 않는다** — 판정 한 줄 + 지휘자가 새로 판단한 것만. 원문은 산출물 경로로 가리킨다.
- **승인 요청은 마지막 한 줄.** 근거를 다시 늘어놓지 않는다(계획서에 있다).
- **내 실수 정정은 한 번, 한 문장.** 같은 정정을 다음 턴에 또 쓰지 않는다.
- 서론·재요약·"지금까지의 정리" 금지. 사용자가 요청할 때만 낸다.

**실험·기록**
- **로컬 CV는 Brier와 함께 LB 환산 점수를 병기한다** (2026-08-07 사용자 지시): `점수 = 100000 × (1 − Brier / 0.2498069)`, **소수점 최대 5자리**(불필요한 뒤 0 없이 — `618.8`이지 `618.80000`이 아니다). **단 6자리 Brier에서 환산한 값은 ±0.20의 불확실성을 가진다**는 점을 함께 적는다(환산 민감도 `Brier 1e-6 = 점수 0.4003`, 6자리 반올림 ±5e-7 → 점수 ±0.2002). 즉 뒤 네 자리는 반올림된 입력의 기계 변환일 뿐 측정값이 아니다. **Brier가 원자료이므로 지우지 말고 환산값을 추가**한다. **LB 점수는 자르지 않는다** — 리더보드 원자료(소수점 10자리)이고 결정론 채점이라 그 자리들이 실제 정보다. ⚠️ **exp_000~exp_008의 Brier는 valid-R 눈금**이라 valid_all 기준 ref를 적용하면 안 된다(환산 열은 `—(valid-R 눈금)`).
- **보정(오프셋·백오프·수축 등) 관련 수치도 전부 환산 점수로 보고한다** (2026-08-07 사용자 지시 — 위 규칙의 확장):
  - Brier로 표현되는 모든 것(이득·손실·arm 간 차이·정책비용)은 **환산 점수를 병기**한다. `−2.3143e-05`만 쓰지 말고 `+9.26423점`을 함께 적는다.
  - **확률 단위 이동폭**(예: `β·d` 최대 0.046687)은 점수로 **직접 환산되지 않는다** — 그 이동이 정답 쪽인지 반대쪽인지에 따라 부호가 갈리기 때문이다. 확률값을 적되, 그 이동이 만든 Brier 변화가 측정돼 있으면 환산 점수를 병기한다. 지어내지 말 것.
  - **"이동폭"이라는 말을 두 뜻으로 쓰지 말 것**: ① **보정 이동폭** = 모델 원본 예측에서 `β·d`만큼 밀린 양 ② **후보 간 예측 차이** = 두 제출물의 최종 예측 차. 둘은 다른 양이므로 이름을 나눠 쓴다.
- **LB 점수를 받으면 즉시 양쪽 기록** (2026-08-05 사용자 지시): 사용자가 제출 결과를 알려주면 지체 없이 ① 로컬 `EXPERIMENTS.md`(해당 실험 행의 LB 열 + 현재 베스트 + 결정 로그) ② 필요 시 `해커톤_전략.md`(환산계수·목표 거리 재계산) ③ **노션 실험 로그 DB 해당 행의 LB 속성·상태** ④ 팀에 공유할 함의가 있으면 질문·논의 DB 공지 — 네 곳을 같은 턴에 처리한다. 어느 하나라도 빠지면 장부가 갈린다.
- **로컬 문서 ↔ 노션은 항상 일치**: 실험·제출·결정은 recorder가 양쪽 동시 기록, 규칙·구조·일정 변경은 지휘자가 같은 턴에 양쪽 갱신 (페이지 ID 맵: `orchestration/팀협업.md`)
- **변경 변인을 전부 파악하고 기록한다** (2026-08-06 사용자 정정 — 규칙의 본뜻):
  - 이건 "한 번에 하나만 바꿔라"라는 **설계 제약이 아니라 기록 정확성 제약**이다. a·b 각각은 무효인데 a+b가 유효한 경우가 실재하므로 **조합 탐색은 오히려 권장**된다.
  - 금지되는 것은 **여러 개를 바꿔놓고 하나만 바꿨다고 적는 것**. 근거: 전 대회에서 실제로 그렇게 기록해 delta 해석이 통째로 무너진 사고가 있었다.
  - 따라서 매 실험·제출에서 ① 대조군 대비 **달라진 것 전부를 열거**하고 ② 효과를 어느 하나에 귀속시키려면 **그것만 바꾼 대조가 있어야** 한다 ③ 없으면 "이 조합의 효과"로만 서술한다.
  - 의도치 않게 딸려 바뀐 것(iter·시드·학습행 수·라이브러리 버전 등)도 변인이다 — 빠뜨리면 같은 사고다.
- ±0.001급 차이를 "노이즈"로 서술 금지 — 채점 결정론 실측 전까지 판단 보류 언어 사용
- 실험 코드·산출물 보존. 임시코드 삭제 후 기억으로 서술 금지
- 결측을 sentinel(0/-1/평균)로 채우기 금지 — 채우려면 결측 플래그 컬럼 별도

**제출물 검증 3단 (2026-08-10 사용자 승인 — "바꿔도 문제가 없다면 바꾸자")**
> 근거: packager 독립 검증 **5회에서 zip의 기능 결함 0건**(찾은 것은 전부 문서·인프라 사실). 반면 제출을 실제로 깨뜨릴 것은 **빌더 자체 게이트**(V의 zip에서 `script.py` 누락 — `zip -q`가 없는 이름에 안 멈춘다)와 **감사**(exp_030 N2 `assert s.notna().all()`이 채점 서버에서 크래시 / dtype 핀이 풀리면 예측 2.6e-03 이동)가 잡았다.

- **A단 — 사후 변환만** (부스터 바이트 동일, stage 4·오프셋 산술만 변경)
  게이트: ① 부스터 sha == 부모 zip ② **항등 앵커** ③ 출력 계약 ④ 규칙 2-4 **두 개**(전체 셔플 + 세그먼트 혼합 100행 단독) ⑤ 두 분기 발동 ⑥ 추론 시간 실측
  **에이전트 2개**(빌더 + 4항목 감사). packager 없음.
- **B단 — 새 부스터, 같은 피처·경계**: A단 + 부스터 상이성 + `get_all_params()` 차이가 `random_seed`뿐 + 표 sha == 부모.
- **C단 — 새 피처 소스·새 경계**: **packager 전면 검증을 유지한다.** (S 때 구종 모델을 통째로 재학습해 sha 대조한 것이 값을 했다.)

- 🟢 **2026-08-28 운영진 답변 — 이 항목의 부담이 줄었다**: *"반드시 리더보드 점수가 소수점 단위까지 완전히 일치해야 하는 것은 아니며…"*. `.cbm` 바이트 재현 불가는 **Phase 3 코드 검증의 장애물이 아니다.** 아래 규칙(게이트로 걸지 마라·모델 동일로 검증하라)은 **그대로 유지**한다 — 우리 내부 검증의 무결성 문제이지 운영진 요구가 아니었다.
- 🔴 **CatBoost `.cbm`은 재학습으로 바이트 재현되지 않는다** (2026-08-13 후보 AG 실측 — **앞으로 어떤 계획서에도 `.cbm` 바이트 재현을 게이트로 걸지 마라. 지휘자가 AG 계획서에 그렇게 적어 원리적으로 불가능한 게이트를 만든 사고가 있었다**).
  근거: 바이트 동일한 OOF 하나 위에서 같은 시드·같은 파라미터로 655라운드를 세 번 적합 → **파일 sha 3개 전부 다름, 잎값 sha 3개 전부 같음**. 다른 메타키는 정확히 둘 — `model_guid`(적합마다 새 UUID)·`train_finish_time`(벽시계). **`.cbm` 바이트 비교는 시계와 난수를 검사한다.**
  - **바이트 동일을 주장해도 되는 것**: 복사·승계한 파일(부모 zip에서 그대로 가져온 부스터), 예측 배열(`.npy`), 출력 CSV. 이들은 재현된다.
  - **재학습을 검증하는 올바른 형태 = 모델 동일**: 잎값 전체 float64 정확 일치 + 트리 수 + 피처 순서 + 모델 기록 파라미터 블록 + `learn_best_error`, **그리고 `model_guid`·`train_finish_time` 외 메타키가 하나라도 다르면 실패**(마지막 조건이 없으면 통과하기 쉬운 약한 검사가 된다).
  - **그 위에 종단 항등 앵커를 얹는다** — 바꾼 값을 부모 값으로 되돌려 **패키지를 통째로 다시 만들고** 출력 CSV sha가 부모와 같은지. 이게 "바꾼 것 하나를 되돌리면 부모가 재현된다"의 유일한 증거다.
- 🔴 **`model/meta.json`에 부스터 트리 수가 기록돼 있고 `aa_infer.py`가 실행 시 대조한다** (2026-08-13 후보 AG 발견 — 빌더가 읽어서가 아니라 `AssertionError`로 터져서 알았다). **부스터를 재학습하거나 반복 횟수를 바꾸면 이 파일도 함께 고쳐야 하고, 안 고치면 채점 서버에서 크래시한다**(제출 횟수 차감 사유). 부스터를 건드리는 모든 계획서에 이 항목을 넣을 것.

  → **시즌 경계에 의존하는 피처·오프셋이 있는 후보는 게이트를 대역 프레임 단독으로 돌리지 마라.** 다음 중 하나를 반드시 병행한다: ① 앵커보다 **뒤**인 행으로 만든 프레임 ② 커버리지를 강제한 합성 프레임 ③ **실제 대회 표본 행**(AI 감사가 5행으로 `has_form=2/5`를 확인해 설계 성립을 증명했다).
  ⚠️ 축퇴 프레임에서 통과한 게이트를 "발동 확인"으로 적지 마라 — 그건 아무것도 시험하지 않은 것이다.
- 🔴 **규칙 2-4 판정은 내용/위치 분리 실험으로 한다 — 100행·1행 단독 검사만으로 판정하지 마라** (2026-08-15 AL·AM 감사가 확립).

  → **가르는 실험**: ① **내용** — 문제 행의 값과 인덱스를 고정하고 **나머지 전 행을 두 프레임 어디에도 없는 행으로 전량 교체** → delta가 **정확히 0.0**이면 다른 행의 내용은 영향이 없다 ② **위치** — 이웃은 그대로 두고 그 행의 인덱스만 바꿔 delta를 확인.
