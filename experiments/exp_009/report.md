## 3. has_profile 플래그 — 실패 (sentinel 가설 기각)

단일변수 체인(valid_all): P0→P0b −0.000020 / **P0b→P1 +0.000107(프로파일 순효과)** / **P1→P2 +0.000032(플래그, 악화)** / P2→P3 −0.000078 / P3→P4 +0.000129.

플래그는 sentinel 손해를 되사오지 못했고, 임퓨터를 우회한 P4가 전 arm 중 최악. 이유는 커버리지 세그먼트에 있다 — **프로파일 없는 행이 원래 더 쉬운 행**이라 P0조차 결측 세그먼트(0.248174)를 有 세그먼트(0.248521)보다 잘 맞힌다. 결측 정보가 이미 `asof_pitcher_*`에 반영돼 있어 플래그가 새 정보를 주지 않는다. 프로파일을 붙이면 有/無 **양쪽 다** 악화(P4는 결측 행이 0.248174→0.248718로 붕괴).
→ **병목은 결측 인코딩이 아니라 피처 자체의 신호 부족.**

## 4. 프로파일 중요도 — 높은 점유율, 제로 페이오프

gain 점유율 **P1 30.9% / P2 31.7% / P4 32.6%** (exp_003 LGBM은 1.5% — 20배). 최고 순위 9위 `recent_offspeed_share` 0.0173. 그런데 성능은 나빠졌다.

기전: RF는 매 분기 112개 중 10개를 뽑는데 프로파일이 65개(58%)를 차지해 **자리만으로** 후보 예산의 절반 이상을 먹는다. **중요도 31%는 유용성이 아니라 예산 잠식의 증거.** 상위는 여전히 base 47이 독식 — `asof_pitcher_success_rate` 0.110 / `asof_pitcher_reverse_rate` 0.096 / `prev5_game_success_rate` 0.063. 이미 투수의 **실제 제구 결과 이력**이 있는데 프로파일이 파는 건 구속·회전수 **물리 프록시**라 덧붙일 게 없다.

exp_003의 "커버리지 80.7%라 과소평가" 변론은 **이번엔 무효** — 커버리지 높은 有 세그먼트에서도 프로파일이 진다.

## 6. 결론

**기각** — 프로파일 65피처는 강한 RF base 위에서 3 fold × 2 눈금 × 4 변형 전부 대조군에 패배. exp_003의 −0.000070은 **약한 LGBM base에서만 성립한 국소 효과**였다. 피처 추가 노선을 접고 RF 규제 스윕으로 전환.

## 7. 다음 제안

1. **`max_features` × `max_depth` × `min_samples_leaf` 스윕을 47피처 위에서** — P0b가 방향을 보여줬고 현재 효과가 확인된 유일한 축. (→ exp_013)
2. 프로파일을 살리려면 65 원시열이 아니라 **2~5개 압축 파생**으로 (열 수가 손해의 기전이므로 부호가 바뀔 여지). 우선순위는 (1) 뒤.
3. **`asof_pitcher_*` 계열 심화** — 상위 6개 중 5개. 구간별·구종별 as-of 성공률, causal shrinkage (→ exp_011).
4. **exp_007 V1의 프로파일 지분 재검토 필요** — 그 −0.000088 개선이 이 결과와 상충.

- **리크 점검 통과**: fold별 as-of(`season <= Y-1`) assert 강제, trackman 2025 부재 assert, 인코더/임퓨터/RF 전부 학습행 fit, valid는 transform/predict만, 현재 행 TrackMan 미사용, test 미참조. fold_2024 valid 행수 assert(253,507/223,497) 통과 — exp_001/007/008과 동일 행 집합.

- **P0b·P3·P4는 fold_2022 미실행**(2 fold 설계) — 표의 빈칸은 결측이지 0 아님.
