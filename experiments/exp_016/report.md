## 2. 게이트 ④ — exp_014의 "미확인 residual" 규명 (실험 성패와 무관한 잔존 지식)

exp_014 §2-②는 `S+M+R ≈ 0.894`의 나머지를 **정체 미확인**으로 두고, 배제되지 않은 가능성으로 "범주 간 겹침"을 명시했다. 행 단위 라벨이 생기자 **산술**이 된다 — 겹침 행이 좌변에서 두 번 세어지므로:

```
1 − (S + M + R) = P(way-off) − P(middle ∧ reverse)
0.097626        = 0.131721   − 0.034095          ← 정확히 성립 (identity_holds: true)
```

교차 확인: 커리어 가중 `S+M+R` 재계산 시 전체 **0.8936**, 500구 이상 465명 **0.9004** — exp_014의 0.894 / 0.900과 일치.

**관측**: residual은 "제3 실패 유형의 비율"이 아니라 **way-off 비율에서 middle∧reverse 겹침을 뺀 값**이다. 제3 모드는 실재하지만(13.17%) 0.10이 그 비율은 아니었다.
⚠️ 이 칸을 "way-off(규정 실패 케이스 ②)"라 부르는 것은 **대응 추정**이다. 확인된 사실은 "success도 middle도 reverse도 아닌 실패가 13.17% 존재한다"까지.

**부수 관측**: R리그 성공률 하락(.5495→.4897)은 **middle 증가**(.130→.179)가 주 성분이고 reverse·wayoff는 대체로 평탄. F리그 2023년 −24pp 단절은 **reverse가 .048→.300으로 폭증**한 것에 집중(원인 미확인).

## 6. 실행자가 내린 설계 판단 (config에 없거나 config를 수정한 것)

**E1 — 4-class → 5칸 배타 분할.** 게이트 ③이 배타성을 기각해 config D4의 B1·B2가 그대로는 정의되지 않는다(`is_wayoff = 1−s−m−r`이 겹침 행에서 정확히 −1). success가 두 실패 모드와 0행 겹치므로 다섯 칸이 분할이 되고, 그 위에서 B1을 5-class로, B2를 4셀(B2c)과 주변확률+포함배제(B2m) 두 형태로 재정의. 두 형태는 기댓값상 동치지만 적합 타깃이 달라 둘 다 측정.

**E2 — 행매칭 대조군 B0b 추가.** 모드 모델은 행을 버려야 하므로, B0b 없이는 "타깃 분해 효과"와 "학습 행 감소 효과"가 교락된다. 측정 결과 행 손실 비용 평균 +3e-6로 B3 이득을 설명하지 못함.

**E3 — fold 경계 리크 차단 (config에 없던 항목).** `is_X[t]`는 t+1 행에서 만들어지므로, 한 투수의 **마지막 학습 행**은 후속 행이 valid 시즌에 있어 라벨이 **valid 결과를 담는다.** `succ_season ≤ train_until` 조건으로 제외: **359 / 366 / 310행**(fold_2022/2023/2024). B3의 OOF 모델에도 같은 규칙(`succ_season < s`) 적용.

**E4 — 다중 서브모델의 iter 정책.** 주안은 **공유 iter**(fold_2023의 합성 valid_all Brier argmin 1개를 승계) — 보고 지표를 직접 최소화하고 1차원 탐색이라 정직하다. 부안으로 모드별 자기 argmin도 측정, 전 안 중 최악(+111e-6). 이유(관측): `is_both`의 자기 argmin이 4라운드라 그 셀이 상수가 되고 합성이 무너진다. **valid 2024는 어느 안에서도 미참조.**

**E5 — B3의 OOF는 시간순 forward-chaining.** 시즌 s 행은 시즌 <s만으로 적합한 셀 모델이 예측. 최초 시즌(2019, train의 18.96%)은 선행이 없어 **NaN 유지** — sentinel 채움은 규율 위반이자 "안다"는 거짓말.

**E6 — B2n·B2m 추가.** config에 없음. B2c가 지면 "분해가 틀렸다"인지 "합의 캘리브레이션이 틀렸다"인지 구분되지 않기 때문. 결과 B2c +41e-6 vs B2n −40e-6 — **분해 자체가 아니라 합성 방식이 갈랐다**는 정황(B2n 단일 시드이므로 여기까지가 관측).

**E7 — `min_data_in_leaf` 미변경.** config D5는 "그 경우를 보고하라"이지 바꾸라가 아니다. 바꿨다면 분해 효과와 튜닝 효과가 교락된다. 경우는 실제 발생했고(§4) **보고만** 한다.

**E8 — 리크 증빙을 코드 바깥에서 재확인.** fold_2024 셀 모델 5개를 저장하고, 별도 스크립트가 **모델 파일에서 피처 목록을 읽어** 복원 컬럼 부재를 확인. 학습 스크립트 자신의 장부가 아니라 산출물이 증거.

**E9 — B3도 시드 반복.** 최선이 B3로 나와 전체 사이클(28 OOF + 스태커)을 시드마다 재실행(총 시간의 약 40%).

## 7. 리크 경계 준수 증빙

1. **복원 라벨은 타깃 전용** — `labels.assert_no_recovered_in_features()`가 **모든 `lgb.Dataset` 생성 직전** 호출(설계행렬·B3 OOF·B3 스태커 각각).
2. **최종 피처 목록에 복원값 없음** — metrics.json `feature_list_used_by_every_submodel` 47열, `is_*` 0개. 저장된 모델 5개에서 재확인(`test_stub_check.json`: `recovered_cols_present: []`).
3. **제외 행**: 복원 불가 792행 + fold 경계 359/366/310행. **valid는 손대지 않았다**(fold_2024 valid_all 253,507 / valid_R 223,497 assert 통과).
4. **규칙 2-4 실증**: test 5행 스텁에서 배치 ↔ 1행씩 ↔ 셔플 배치의 합성 P(success) **max diff 0.0** (B0b·B2c·B2n 세 경로 전부).
5. rolling-origin 3 fold, 랜덤 KFold 없음. fold_2022는 선행 fold가 없어 오라클 — 실험 간 비교 불가. B3의 fold_2023도 오라클(B3는 2 fold만 실행)이나 fold_2024의 iter는 fold_2023 argmin 승계라 정책상 정직.

## 8. 결론

- **채택: B3 스태킹** — fold_2024 valid_all **0.248191**(seed 42) / 3시드 평균 **0.248208**, 대조군 대비 평균 **−0.000055**, 3시드 동부호, B0 시드 std의 18배. **신규 로컬 베스트**(환산 618.4 → 640.1).
- 가설은 **부분적으로 지지된다**: 모드를 나눠 **직접 합성**하는 것(B2c)은 졌고, 모드 확률을 **표현으로 넣는 것**(B3)이 이겼다. "분해가 신호를 더 뽑는다"보다 **"모드 확률이 base 이진 모델에 없는 정보를 담고 있다"**에 가까운 관측이다.
- ⚠️ 목표선 1,061점까지는 여전히 거리가 있다.

## 9. 특이사항·의심 지점

- **에러·경고 0건.**
