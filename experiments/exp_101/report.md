## 가설
팀 원장에서 살아 있는 유일한 범주가 "팔 추가"(전이계수 0.574)다. exp_096 이 닫은 것은 *같은 99열 위의 다른 MLP 아키텍처*였지 **다른 모델 계열**이 아니다. TabPFN 은 합성 prior 로 사전학습된 완전히 다른 계열이라 구조적으로 가장 멀다 — S103 교환율(ρ 0.01 = 단독 15.82점)에서 ρ 를 크게 내릴 수 있으면 약해도 번다.

## 변경점 (전부 열거)
- 새 모델 계열: `tabpfn==8.4.0`, 체크포인트 `tabpfn-v2-classifier-v2_default.ckpt` (29,009,539 B)
- 입력: exp_097 이 고친 f64 표준화 프레임 `X_f64_oot23.npy` (1,475,092 × 94), 딥 팔과 **같은 열**
- 문맥: train(season ≤ 2023) 1,116,277행에서 고정 seed 로 뽑은 20,000행 동결표
- 면·상수·핀·부트스트랩: exp_097 `src/sB1_rebase.py` 를 그대로 이식 (2팔 기준선 26.269817382706947 전 자리 재현 확인)
- 두 판본을 쟀다: ① 단일 문맥 20k ② 겹치지 않는 20k 문맥 **5개 배깅**(총 100,000행)

## 결과

### 관문 A — 통과
- **라이선스**: Prior Labs License = *Apache 2.0 with ADDITIONAL PROVISION* v1.2. 조항 1~9 는 Apache 2.0 과 동일하고 조항 10 은 귀속 표시 요구뿐 — **NC 조항 없음**. 출하 시 LICENSE 사본 동봉 + "Built with PriorLabs-TabPFN" 표시가 의무.
- **라이브러리 봉인**: 채점 서버 기본 패키지를 복제한 venv 에서 **vendoring 만으로** fit+predict 성공. 빠져 있던 것은 정확히 `pydantic` · `pydantic_settings` · `einops` 셋(13.0 MB). `safetensors`·`huggingface_hub`·`filelock` 은 기본 설치된 transformers 4.46.3 / accelerate 1.9.0 이 이미 끌고 온다.
- 🔴 **config 전제 둘을 정정한다**: ① "pip install 이 안 된다" — 대회정보.md:99-103 이 설치 10분 + 설치 목적 인터넷을 허용하고 우리 CP 패키지가 실제로 catboost/lightgbm 을 그렇게 깐다. ② "GPU 근거 없음" — 대회정보.md:104-106 이 **NVIDIA L4 22.4GiB / CUDA 12.8 / 6 vCPU** 를 명시한다.

### 관문 B — 실패 (외삽 아님)
CPU 6스레드로 벽시계 **1,686초**(CPU 시간 2:45:56, 5.9 스레드 상시) 동안 **첫 5,000행 청크가 끝나지 않았다.** 즉 예산 전체를 다 써도 프레임의 2% 청크 하나를 못 끝낸다 — 부분 측정을 곱한 값이 아니라 직접 관측이다. 전량 환산 하한 **82,800초(23시간)**, 판정선 초과 **150배 이상**.

GPU(A5000, 단독 실행 창)로는 245,789행 **207.4초**(1,200.8 행/초). GPU/CPU 비 **384배 이상**. 채점 서버 여유는 484초이므로 **L4 가 A5000 대비 2.33배 이내로 느리면 들어간다** — L4 는 fp16 텐서 처리량이 비슷하고(121 vs 117 TFLOPS) 대역폭이 2.56배 낮아 1.3~2.5배로 추정되나 **우리 장부에 GPU 환산 실측이 없다.** 그리고 관문C 최강 판본(배깅 5)은 A5000 에서 **1,059초** — L4 환산 전에 이미 여유의 2.19배다.

**시간-정확도 곡선** (질의 30,000행, 이 부분집합의 상수예측 기준선 −77.12):

| 4,096 | 4 | 23.7 | 0.5119 | −117.51 |
| 10,000 | 4 | 46.8 | 0.5366 | 331.93 |
| **20,000** | **1** | **39.5** | **0.5406** | **354.43** |

단일 문맥은 **20k 에서 꺾이고 40k 에서 되레 나빠진다.** 그런데 겹치지 않는 20k 문맥 5개를 배깅하면 전량 valid 에서 291.0 → **665.7** 로 계속 오른다. → **벽은 본 행 수가 아니라 한 번에 넣는 문맥 길이다.** 그 구조가 비용을 배깅 수만큼 선형으로 곱한다.

**규칙 2-4**: 문맥은 train 동결표이고 코드가 질의·문맥 교집합 0 을 assert 로 강제한다. KEEP 8행을 고정하고 나머지 질의 1,992행을 **한 행도 안 겹치는 행으로 전량 교체** → max|Δ| = **0.0**. 인덱스만 이동 → **0.0**. (단독 vs 배치 2.712e-04 는 배치 *크기* 에 따른 GPU 축약 순서 차이이지 다른 행의 *내용* 이 아니다 — 내용 검사가 0.0 인 것이 증거다.)

## 결론 — 기각

1. 🔴 **가장 다양한 팔이었고 그래서 죽었다.** ρ(z_mate) = 0.6861 은 S115 시드 대역 [0.9106, 0.9393] 아래는 물론 딥 팔 0.8930 보다도 훨씬 낮다 — **지금까지 잰 어떤 팔보다 멀다.** 그런데 이득은 +0.074 였다.
2. 🔴 **S72 가 정확히 재현됐다.** 배깅으로 단독을 403.7 → 679.3 (**+275.6**) 올리자 ρ 가 0.6861 → 0.8578 (**+0.1717**) 로 같이 올라갔고, 순 이득은 **0.10점** 움직였다. 다양성의 상당 부분이 잡음이었고, 잡음을 깎으면 다양성도 깎인다.
3. 🟢 **S103 교환율이 다른 모델 계열에서도 성립했다.** ρ 를 0.207 낮추고 단독을 461 낮추면 S103 단가로 +63.9 − 90.1 = **−26.2**, 즉 딥 팔의 몫을 정확히 상쇄한다 — 관측(2팔 대비 +0.07)과 부호·자릿수가 맞는다. 그 회귀는 딥 팔 계열 안에서 적합됐는데 **완전히 다른 모델 계열에 외삽해도 맞았다.**
4. ⚠️ **시간과 신호가 같은 손잡이에 묶여 있다.** 신호를 사려면 배깅 수를 늘려야 하고 그것이 곧 시간이다. 들어갈까 말까 한 지점(배깅 1, 207초)의 이득이 +0.074 다.

## 다음 제안

- **이 축은 닫는다.** TabPFN 슬롯 안에 훑을 것이 없다 — 문맥 길이는 벽, 배깅은 시간, 신호는 두 판본 다 t < 0.24.
- 🟢 **재사용할 사실 하나**: ρ 0.686 짜리 방향이 **실재한다**. 우리 팔 군 전체가 0.86~0.94 대역에 몰려 있다. 문제는 그 방향의 팔이 약했다는 것뿐이다. S103 회귀로 환산하면 **ρ 를 0.89 → 0.75 로 내리면서 단독을 850 에 유지하는 팔은 +43** 이다. 어디서 그런 팔이 나올지가 남은 질문이다.
- ⚠️ **GPU 후보를 다시 검토하기 전에 L4 ↔ A5000 환산 계수를 재라.** 지금은 손익분기(2.33배)만 알고 실제 값을 모른다 — S122 의 GPU 판이 없다.
