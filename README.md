# LG Aimers 9기 — 투구 제구 성공 확률 예측

DACON 온라인 해커톤(2026.08.05 ~ 09.02) 참가 기록. **최종 1167.7129점 · 49위 / 1,087팀**.

> 이 저장소의 자산은 모델이 아니라 **의사결정 기록**이다.
> 130여 개 실험, 138회 제출, 333개의 단서(clue)가 무엇을 시도했고 무엇이 왜 실패했는지 전부 남아 있다.

---

## 문제와 지표

투수의 다음 투구가 의도한 코스로 갈 확률을 예측한다. 평가 지표는 **Brier Skill Score** —
`점수 = 100000 × (1 − Brier / 0.2498069)`.

이 지표가 설계 전체를 정했다. Brier 는 순위 능력이 아니라 **확률 보정(calibration)** 을 채점한다.
실측으로 우리 모델들의 AUC 는 0.529~0.545 로 순위 능력 자체가 얇았다.
→ 자원을 "더 센 모델 찾기"가 아니라 **결합 계수와 보정 곡선을 정밀하게 맞추는 쪽**에 넣었다.

## 검증 설계

- **rolling-origin**: `train ≤ 2023 → valid 2024` 하나만 비교 기준으로 고정. 랜덤 KFold 금지.
- test 는 2025 시즌이다. as-of 표는 **시즌 s 행이 s−1 이하 시즌 표만 보도록** 만들어, 2025 test 행이 `upto_2024` 표를 보는 인과 구조와 일치시켰다.
- 모든 시계열 집계는 `shift(1)`, 현재 행의 TrackMan 물리량은 입력에서 제외(test 에 없다).

🔑 대회 내내 반복 확인한 것: **같은 해 안에서 겹을 아무리 갈라도 "연도 전이"는 시험되지 않는다.**
투수 ID 2겹 교차적합을 통과한 축이 시즌을 넘자 부호가 뒤집혀 −8.32점을 잃은 사례가 실제로 있다([단서 S314](ledger/단서.md)).

## 모델

라벨이 `success + reverse + middle ≈ 0.90` 으로 분해된다는 관찰에서 출발한 **B3 모드 스태킹** —
셀 부스터 4개(`is_mid_only`·`is_rev_only`·`is_both`·`is_wayoff_true`) → 스태커 1개, CatBoost.
최종 제출은 팔 다섯 개를 로짓 공간에서 결합한 뒤 사후 보정 다항식을 얹는다.

```
p = expit( α·z + β₂·z² + β₃·z³ + d + Σ 오프셋 축 )
```

## 이 프로젝트에서 만든 측정 방법론

성능보다 **측정 규율**에 시간을 더 썼고, 그게 점수를 냈다.

| 도구 | 무엇 | 실측 |
|---|---|---|
| **라벨 없는 곡률 측정** | 라벨 0개·15분에 2차식 곡률항을 잰다. LB 한 점만 있으면 꼭지점·천장·잔여가 나온다 | 단, 실측의 절반으로 나오는 계통 편향이 있었다(1.96배·2.06배) → **곡률 2배 최악값을 견디는 지점에 선다** |
| **항등 앵커** | 바꾼 상수를 되돌려 패키지를 통째로 다시 만들면 부모의 출력 CSV sha256 이 재현돼야 한다 | 통과하면 표·어휘·dtype·피처 순서·산술이 같음이 한 번에 증명된다 |
| **짧게 서기** | 계산된 꼭지점보다 짧게 선다 | 두 축에서 각각 1.5점·0.8점을 아꼈다 |
| **차분 회계** | 같은 축을 같은 진폭으로 실은 두 후보의 차분은 그 축을 정확히 소거한다 | 진 제출에서 다른 축의 부호 반전을 적발했다 |
| **사전 등록 문턱** | 채택 기준과 σ 를 결과 보기 전에 등록하고, 결과를 보고 바꾸지 않는다 | 표본 안 +7.39 / 교차적합 −1.08 인 과적합을 잡아냈다 |

## 사례 연구 — 마지막 날 아침 3시간, +6.82

| 발 | Δ | 무슨 일 |
|---|---|---|
| 1 | **+1.00** | 미측정 축 결합 |
| 2 | **−6.07** | 3차항 부호를 반대로 걸어 크게 졌다 |
| 3 | **+2.65** | **진 발과 직전 발의 차분**에서 진짜 범인을 찾았다. 두 후보가 같은 축을 같은 진폭으로 실었으므로 차분에서 그 축이 소거되고, 남은 몫이 다른 축의 반전을 지목했다 |
| 4 | **+1.36** | 두 축 꼭지점 착륙 |
| 5 | **+1.93** | 4점 연립해로 최종 착륙 |

순위가 제출 이력의 **최대값**으로 정해진다는 구조를 이용했다 — 진 제출이 순위를 깎지 않으므로,
부호가 불확실하면 접지 않고 작은 프로브로 샀다.

## 무엇이 닫혔나 (측정으로 기각한 것)

포트폴리오로서 더 정직한 부분이다. 대부분의 시도는 실패했고, **왜 실패했는지가 기록돼 있다.**

- 새 팔 계열 — XGBoost·RandomForest·ExtraTrees·HistGB·CatBoost **5개 모형족 13설계 전부 문턱 미달**.
  상관 ρ 는 알고리즘이 아니라 입력 열이 정한다는 것을 8설계로 확인했다.
- 결합 규칙 세그먼트화 — 표본 안 +7.39 → 교차적합 **−1.08**(전량 과적합)
- 딥 팔의 학습량·폭·초기화, 시드 확장, TabPFN, 트랙맨 물리 계열

🔑 마지막에 값을 준 것은 새 모델이 아니라 **아무도 적합하지 않은 채 남아 있던 결합 계수**였다.
설정 파일이 스스로 `w_fitted: false` 라고 적어둔 파라미터가 있었고, 그것을 맞춰 +0.89 를 얻었다.

## 포함하지 않은 것

- **대회 데이터** — 대회 규정상 외부 유출 금지(실격 사유). `.gitignore` 로 이중 차단했다.
- **학습된 모델 바이너리·제출 zip** — 용량(약 18GB)과 팀원 자산 포함 문제.
- **팀원이 학습시킨 팔의 코드** — 3인 팀이었고, 최종 앙상블의 절반은 팀원이 만든 모델이다. 이 저장소에는 **본인이 작성·수행한 부분만** 담았다.
- **PII** — 팀원 실명·연락처·서버 접속 정보는 마스킹했다.

## 재현성

배포 모델은 학습 코드로 **잎값까지 재현**된다 — 시드 42 재적합 결과 출하 부스터와
잎값 `max|Δ| = 0.0`, 잎가중치 일치, 분할 상이 트리 0개.

🔴 단 `.cbm` **바이트 비교는 재현 판정에 쓰지 않는다.** 파일 안에 `model_guid`(적합마다 새 UUID)와
`train_finish_time`(벽시계)이 들어가 같은 모델도 파일 해시가 매번 다르다.
같은 시드·같은 파라미터로 세 번 적합해 **파일 sha 3개 전부 다름 / 잎값 sha 3개 전부 같음**을 실측 확인했다.
자세한 것은 [docs/04_실행환경.md](docs/04_실행환경.md).
